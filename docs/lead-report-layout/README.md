# リード向け診断レポート レイアウト案（2026-08-03）

`resources/views/reports/lead-pdf.blade.php` をA4横のスライド構成に作り直すための
レイアウト案です。配色はレジェンダ・コーポレーションのコーポレートサイト
（https://www.leggenda.co.jp/）に合わせています。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `report-layout-draft.html` | レイアウトのHTML。Bladeへ移植する元。 |
| `report-layout-draft.pdf` | 上をA4横で印刷したもの。見た目の確認用。 |
| `brand-wheel-framework.png` | 前置きページで使う説明図（分析結果に依存しない固定アセット）。 |
| `radar-sample.png` | レーダー図のサンプル画像。 |
| `leggenda-logo.png` | コーポレートロゴ。表紙・各ページ右下・最終ページで使用。 |

## 重要な前提

**数値・文章はすべてダミーです。** 実際の診断結果ではありません。全ページの右上に
「サンプル（ダミーデータ）」を入れてあります。本番テンプレートへ移植する際は、
この表示を必ず外してください。

**このPDFはChromiumで印刷したもので、dompdfの出力ではありません。** 見た目が
そのまま再現される保証はありません。移植後は必ず実際にdompdfでPDFを生成し、
目で確認してください。

## 配色（レジェンダのコーポレートサイトから抽出）

コーポレートサイトの computed style から実際に取得した値です。

| 用途 | 色 | 出典 |
| --- | --- | --- |
| コーポレートの藍 | `#1D2088` | サイトの「人事労務」見出し色 |
| 朱赤 | `#E95446` | サイトの「採用強化」見出し色 |
| 青緑 | `#3496AF` | サイトの「人事DX」見出し色 |
| 本文 | `#393636` | サイトの body 文字色 |
| 面 | `#F5F5F5` | サイトの背景グレー |
| 罫線 | `#E0E0E0` | — |

これを本レポートには次のように割り当てています。

| 役割 | 色 | 備考 |
| --- | --- | --- |
| 見出し帯・キーメッセージ帯・六角ラベル | `#1D2088` | 白文字 13.0:1 |
| グループ帯「会社の魅力」 | `#1D2088` | 白文字 13.0:1 |
| グループ帯「会社との距離」 | `#2C7F96` | `#3496AF` は白文字 3.4:1 で不足のため暗くした（4.6:1） |
| グループ帯「仕事の魅力」 | `#C03A28` | `#E95446` は白文字 3.6:1 で不足のため暗くした（5.4:1） |
| レーダー 自社 | `#3A3FC0` | `#1D2088` そのままはチャート用の明度帯を外れるため明るいステップを使用 |
| レーダー 競合 | `#E95446` | サイトの値そのまま |

**系列色の組み合わせ `#3A3FC0` / `#E95446` は検証済みです。** 色覚多様性を含む
6項目のチェックをすべて通過しています（CVD分離 ΔE 25.7、通常視 ΔE 37.7、
背景コントラストいずれも基準以上）。この2色を変更する場合は、必ず同じ検証を
やり直してください。目視で判断しないこと。

**グループ名から色名を外しています。** 元のスライドは「青／会社の魅力」
「緑／会社との距離」「赤／仕事の魅力」でしたが、配色をレジェンダに合わせた結果、
緑が青緑に変わり色名と実際の色が食い違うため、「会社の魅力」「会社との距離」
「仕事の魅力」としています。バックエンドが生成する文言（`BrandWheelComparisonSummaryComposer`）
には色名が含まれていないことを確認済みなので、この変更による不整合はありません。

## ロゴの扱い

`leggenda-logo.png`（512×94、白背景）を次の3箇所で使っています。

- 表紙: タイトルの上に中央配置（幅72mm）
- 各内容ページ: 右下に小さく（幅30mm）
- 最終ページ（ご相談）: 見出しの上に中央配置（幅60mm）

各ページ下部には **20mm の余白を確保** してあります。確保しないと、キーメッセージの
紺帯の上にロゴが重なります（実際に一度重なりました）。脚注も右端を 52mm 空けて
ロゴの手前で折り返すようにしています。**中身を増やす場合は、この余白を必ず維持し、
生成したPDFで重なりが無いことを目で確認してください。**

ロゴは `backend/resources/` 配下に静的アセットとして置き、base64 で埋め込んでください。

## フォントについて

レジェンダのサイトは **Noto Sans JP**（見出し weight 600）です。ただし
`PdfReportGenerator` のコメントにあるとおり、`fonts-noto-cjk` は TrueType Collection
(.ttc) でしか配布されておらず dompdf 側の対応が不安定なため、現状は IPAexゴシックを
埋め込んでいます。**この案でもフォントは IPAexゴシックのままにしてあり、配色と構成で
ブランドに寄せています。** Noto Sans JP を使いたい場合は、Google Fonts が配布する
単体 .ttf を Dockerfile で配置する必要があります（別タスク）。

## dompdfの制約（このHTMLで守っていること）

- flexbox・CSS grid は使えない。段組みはすべて `<table>` で組んでいる
- `clip-path` は使えない。スライドにある六角形のラベルは矩形で代用している
- `box-shadow` は使わない。`border-radius` も最小限にとどめている
- 画像は `<img src="data:image/png;base64,...">` で埋め込む
  （このドラフトでは読みやすさのため外部参照にしている）

## 前置きページ（2ページ目）について

`brand-wheel-framework.png` は分析結果に依存しない固定の説明図です。レポートごとに
生成する必要はありません。`backend/resources/` 配下に静的アセットとして置き、
テンプレートから base64 で埋め込んでください。`BrandWheelHexagonRenderer` は
通さないこと（毎回 rsvg-convert を走らせる意味がありません）。

図の下位要素24項目は `config/brand_wheel.php` と一致していることを確認済みです。
**config を変更した場合はこの図も作り直す必要があります。**

このページには次の文言を必ず残してください。短くしたり削ったりしないこと。

> 読み取れなかった項目は、その魅力が「無い」という意味ではありません。
> サイトにそう書かれていない、というだけです。

この診断で最も誤解を招く箇所であり、結果を見せる前に置いておく必要があります。

## レーダー図について

サーバ側にこの図を生成する実装はまだありません。既存の
`BrandWheelHexagonSvgBuilder` は「1サイト分の6扇形」で、これとは別物です。
流用せず、別クラスを作ってください。

幾何計算は `frontend/src/features/lead/lead-brand-wheel.tsx` の
`wheelPoint()` / `axisRatio()` と同じ式にします。

- 0時方向を起点に時計回り
- 半径は `matched_count / max_count`
- `max_count` が 0 の軸は 0 として扱わず、点を打たない
- 目盛りリングは `max_count` 分。テンプレートに 4 や 5 を固定値で書かない
- 自社 `#3A3FC0` / 競合 `#E95446`、`fill-opacity` 0.16、点は白フチ付き
- 競合の分析が success でない場合は自社の面だけを描く

PNG化は既存の `BrandWheelHexagonRenderer` をそのまま使ってください
（rsvg-convert・不透過背景・IPAexゴシック）。新しいラスタライズ経路は作らないこと。
PNGが生成できなかった場合は図を省略し、軸ごとの件数の表だけで成立させます
（画像の失敗がレポート生成全体を止めてはいけない、という既存メールと同じ方針）。

## 4観点の扱い

現行のテンプレートは指標ラベルを44項目そのまま列挙しており、社内の指標名が
そのまま社外に出ています。観点ごとに「見出し・判定・理由1文」だけに畳んでください。

ただし「取得できなかった項目は0点として扱わず算出対象から外している」旨と、
カバー率・確信度は残します。誠実性の維持に必要な情報なので、これは畳みません。

Word版も同じ扱い・同じ配色に揃えてください。
